# 자비스 디자인 방향 · Quiet personal stylist

작성 기준: 2026-09-09. 기존 MVP 코드와 공식 서비스 소개를 검토한 디자인 제안이다. 이 문서는 제품의 목표와 판단 기준을 기록하며, 모든 목표 기능이 구현됐다는 의미는 아니다.

## 1. 만들고 싶은 인상

“내 옷장을 이해하고, 아침에 필요한 선택 하나를 먼저 준비해 주는 조용한 패션 비서.”

사용자의 핵심 과제는 패션 정보를 많이 보는 것이 아니라 오늘 무엇을 입을지 결정하는 것이다. 첫 화면은 짧은 브리핑, 한 벌의 코디, 명확한 다음 행동에 집중한다. 옷장과 입력 기능은 이 결정을 뒷받침한다.

기존의 흰색·분홍·보라 정체성은 유지하되 채도와 사용 면적을 줄인다. 옷과 타이포그래피가 가장 먼저 보이고, 브랜드 색은 선택 상태와 짧은 비서 메시지에 남긴다. 여기서 ‘세련됨’은 장식을 늘리는 것이 아니라 정보의 우선순위를 분명하게 만드는 방향으로 정의한다.

## 3. 레퍼런스와 자비스에 가져올 원리

공식 수상 사실과 서비스가 설명하는 기능, 자비스에 적용하려는 디자인 해석을 분리했다. 수상·평점·다운로드 수가 특정 색상이나 비율의 효과를 증명하지는 않는다.

### Tiimo — 먼저 정리해 주는 일상 비서

- 확인한 사실: Tiimo는 **2025 App Store Awards의 iPhone App of the Year 수상작**이다. Apple은 시각적 계획과 AI를 통한 실행 가능한 다음 단계 제시를 설명한다. [Apple 공식 수상 발표](https://www.apple.com/newsroom/2025/12/apple-unveils-the-winners-of-the-2025-app-store-awards/)
- 공식 서비스 소개: 입력하거나 말한 일을 작은 단계와 하루 계획으로 정리하는 접근을 안내한다. [Tiimo 공식 사이트](https://www.tiimoapp.com/)
- 디자인 해석: 자비스도 첫 화면에서 사용자가 질문을 작성하기 전에 ‘오늘을 위한 제안’을 보여준다. 긴 대화창 대신 짧은 브리핑과 바로 선택할 수 있는 결과를 제공한다.
- 적용: “오늘은 가볍게, 단정하게.” → 코디 한 벌 → “오늘 이대로 입기”. 다른 코디 요청은 보조 행동이다.

### Structured — 오늘 해야 할 일을 한눈에

- 확인한 사실: Structured는 **2025 App Store Awards의 iPad App of the Year 최종 후보**다. 수상작으로 표현하지 않는다. Apple은 읽기 쉬운 타임라인으로 하루를 시각화하는 점을 언급했다. [Apple 공식 최종 후보 발표](https://www.apple.com/newsroom/2025/11/apple-announces-finalists-for-the-2025-app-store-awards/)
- 공식 서비스 소개: 할 일과 일정을 하나의 시각적 타임라인에 모은다. [Structured 공식 사이트](https://structured.app/)
- 디자인 해석: ‘오늘’이라는 시간 범위를 명확히 하고, 현재 필요한 맥락부터 보여 주면 옷장 전체를 탐색하는 부담을 줄일 수 있다.
- 적용: 날짜와 상황 선택을 간결하게 표시한다. 날씨나 일정이 실제로 연결되지 않았다면 임의 정보를 실시간 브리핑처럼 표현하지 않는다.

### Indyx — 내 옷이 주인공인 옷장

- 확인한 사실: 공식 안내에서 자동 배경 제거, 카테고리·브랜드·색상 태그, 드래그앤드롭 코디 보드, 코디 캘린더를 설명한다. [Indyx 기능 소개](https://www.myindyx.com/how-it-works)
- 디자인 해석: 의류를 정돈된 배경 위에 배치하는 플랫레이 구성이 ‘무엇을 함께 입는지’를 빠르게 이해하게 한다. 자비스의 상품 사진 면적과 비율을 통일하고 정보 라벨은 사진 아래로 모은다.
- 적용: 코디는 상의·하의·신발이 한 장면에 보이게 구성한다. 옷장에서는 2열 그리드와 충분한 이미지 여백을 사용한다. 타사 화면, 상품 사진, 로고를 그대로 복제하지 않는다.

### Whering — 이미 가진 옷을 다시 활용

- 확인한 사실: 사진이나 온라인 상품 이미지로 옷을 추가하는 흐름을 소개한다. 별도 FAQ에서는 개인 스타일과 날씨를 바탕으로 등록한 옷의 조합을 제안하는 W Pick을 설명한다. [Whering 시작 안내](https://whering.co.uk/how-it-works), [Whering 코디 추천 FAQ](https://whering.co.uk/faq/outfit-suggestions-on-Whering?language=en-GB)
- 디자인 해석: 자비스의 주된 가치는 새 상품 구매보다 보유한 옷을 쉽게 꺼내 입는 데 둔다. 추가와 추천의 흐름을 짧게 연결하고 많은 등록 옵션을 동시에 펼치지 않는다.
- 적용: 빈 옷장에서는 첫 옷 등록을 가장 크게 안내한다. Gmail·캡처는 실제 연결 여부에 맞춰 보조 경로로 제공한다. 소셜 피드와 쇼핑 기능은 이번 MVP 범위에서 확장하지 않는다.

## 4. 색상과 사용 비율

다음 비율은 **자비스를 위한 초기 디자인 가설**이다. 업계의 보편 법칙, 레퍼런스 앱의 정확한 색상 측정치, 사용자 검증 결과가 아니다. 상품 사진을 제외한 UI 면적을 기준으로 대략적인 균형을 확인한다. 화면마다 꼭 100%로 계산해 맞출 필요는 없다.

| 역할 | 색상 | 시작 비율 | 사용 위치 |
| --- | --- | --- | --- |
| 따뜻한 흰색 + 흰색 | `#FAF9F6`, `#FFFFFF` | 약 80% | 전체 배경, 카드, 주요 여백 |
| 스톤 뉴트럴 | `#F0EDE7` | 약 12% | 의류 보드 배경, 보조 영역, 입력 바탕 |
| 페일 라벤더 + 블러시 | `#EDE8F5`, `#F7E9E9` | 합계 약 5% | 비서 메시지, 작은 선택 영역, 부드러운 브랜드 강조 |
| 그래파이트 | `#252525` | 약 3% | 주요 글자, 주 버튼, 선택 아이콘 |

보조 강조색 `#6F597E`는 흰색 위의 링크·선택 아이콘처럼 작은 면적에 사용한다. 주요 행동 버튼은 그래파이트 바탕과 흰색 글자로 안정적인 대비를 준다. 화면 전체를 그라데이션으로 덮지 않고, 필요할 때만 작은 비서 영역 안에서 아주 낮은 대비로 사용한다.

### 색 대비 확인

WCAG의 일반 크기 텍스트 기준은 최소 4.5:1이다. 아래 값은 지정한 HEX 색을 sRGB 상대 휘도 공식으로 계산한 근삿값이며, 전체 화면의 접근성 인증을 뜻하지 않는다. [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

| 글자 / 바탕 | 계산 대비 | 사용 판단 |
| --- | --- | --- |
| `#252525` / `#FFFFFF` | 약 15.33:1 | 본문·버튼 대비 충분 |
| `#6F597E` / `#FFFFFF` | 약 6.17:1 | 일반 글자 가능 |
| `#6F597E` / `#FAF9F6` | 약 5.86:1 | 일반 글자 가능 |
| `#6F597E` / `#EDE8F5` | 약 5.13:1 | 일반 글자 가능 |

실제 색과 투명도, 그라데이션이 바뀌면 재계산한다. 선택 여부와 오류는 색만으로 전달하지 않고 라벨, 테두리, 아이콘을 함께 사용한다.

## 5. 글자와 공간

아래 수치는 모바일 화면 설계의 시작 토큰이다. 폰트와 기기별 렌더링, 시스템 글자 확대에서 확인하며 조정한다.

| 항목 | 기준 |
| --- | --- |
| 큰 제목 | 30~36, 보통 600~700 굵기, 최대 2줄 |
| 화면/섹션 제목 | 20~24 / 18~20 |
| 본문·버튼 | 15~16, 본문 줄간격 약 1.45~1.6 |
| 보조 라벨 | 12~13; 핵심 안내를 더 작게 줄이지 않음 |
| 기본 여백 | 4·8·12·16·24·32 단계 |
| 화면 좌우 패딩 | 20~24 |
| 카드 곡률 | 18~24; 작은 컨트롤은 10~14 |
| 주 버튼 높이 | 50~54 |
| 터치 영역 | 주요 버튼/아이콘에 최소 44×44를 제품 설계 목표로 적용 |

한국어는 읽기 쉬운 시스템 산세리프를 기본으로 한다. 넓은 자간의 영어 대문자 문구를 보조 정보마다 반복하지 않는다. 제목·본문·보조문구의 단계가 한눈에 보이도록 굵기와 여백을 함께 조절한다. 그림자는 얇게 사용하고 모든 카드를 상자에 넣는 패턴은 피한다.

## 6. 화면별 설계 기준

### 오늘

1. 날짜 또는 짧은 인사로 오늘의 화면임을 알린다.
2. 한두 줄의 비서 브리핑을 보여 준다.
3. 가장 어울리는 코디 한 벌을 크게 제안한다.
4. 추천 이유는 한 문장으로 설명한다.
5. 주 행동은 ‘오늘 이대로 입기’. ‘다른 조합 보기’는 보조 행동으로 둔다.

매번 빈 채팅 입력창부터 보여 주지 않는다. 대화를 도입할 경우 “더 편하게”, “신발 바꿔줘”처럼 결과를 수정하는 짧은 요청을 우선 고려한다. 현재 추천이 샘플/규칙 기반이면 AI가 개인 데이터를 분석한 것처럼 표시하지 않는다.

### 내 옷장

등록한 옷의 수, 필터, 동일 비율의 의류 이미지가 중심이다. 화면 위의 `+`에는 ‘옷 추가’ 접근성 라벨을 붙인다. 분류·색상·브랜드를 전부 크게 나열하지 않고 이름과 핵심 정보 한 줄만 노출한다. 등록한 옷이 없을 때와 필터 결과가 없을 때의 안내를 구분한다.

### 옷 추가

처음에는 필요한 정보만 받는다. 이름과 분류를 중심으로 구성하고 선택 정보는 아래로 둔다. Gmail 가져오기와 캡처 분석은 각각 실제 구현 범위에 맞는 명칭과 상태를 표시한다. 사용자의 이메일 전체를 이미 읽은 듯한 문구를 피한다.

### 내 정보

로그인 상태, 저장 상태, 연결 관리를 한곳에 둔다. 데이터베이스 제품명이나 개발 체크리스트는 제품 화면에서 제거하고 개발 문서에 둔다. 저장 성공·실패를 짧고 명확하게 알리고, 실패 시 다시 할 수 있는 행동을 제공한다.

### 시작 화면

서비스 약속 한 문장과 제품의 결과물을 먼저 보여 준다. “내 옷으로, 오늘을 가볍게.”처럼 범위를 이해할 수 있는 문구를 사용한다. 체험 진입을 제공한다면 ‘샘플 옷장 둘러보기’라고 표현해 실제 데이터로 착각하지 않게 한다.

## 7. 말투와 상태 표현

자비스의 비서 말투는 짧고 침착하게 유지한다. 기능을 과장하거나 사용자 성향을 추정해 단정하지 않는다.

| 상황 | 표현 방향 |
| --- | --- |
| 코디 제안 | “단정한 상의에 편한 바지를 골랐어요.” |
| 정보가 충분하지 않음 | “상의와 하의를 추가하면 조합을 볼 수 있어요.” |
| 샘플 체험 | “샘플 옷장으로 둘러보고 있어요.” |
| 계정 연결 전 | “로그인하면 내 옷장을 저장할 수 있어요.” |
| 실제 저장 성공 | “옷장에 저장했어요.” |
| 로컬/일시 저장 | “지금 화면에 추가했어요.” — 서버 저장으로 오해시키지 않음 |
| 네트워크 실패 | “저장하지 못했어요. 연결을 확인하고 다시 시도해 주세요.” |

추천 적합도 백분율, 실시간 날씨, ‘자동 연결 완료’ 같은 문구는 실제 근거와 구현이 있을 때만 사용한다. 샘플 데이터는 보기 좋은 화면을 위한 자료이며 사용자의 실제 구매/취향/날씨 정보가 아니다.

## 8. 다음 검증

레퍼런스의 좋은 평가를 자비스의 사용성 결과로 대신하지 않는다. 첫 디자인 적용 후 스터디 참여자에게 다음 과제를 주어 확인한다.

- 처음 보는 화면에서 이 앱이 무엇을 해 주는지 자기 말로 설명하기.
- 예시 코디를 보고 오늘 입을 옷 결정하기.
- 내 옷 한 벌 추가하기.
- 샘플과 실제 저장/연결 상태 구분하기.

과제 완료 여부, 첫 클릭, 망설인 지점, 실제/샘플 상태 오해를 기록한다. ‘깔끔하다’는 인상 질문과 ‘혼자 과제를 끝냈는가’라는 사용성 관찰을 함께 본다. 필요하면 기존안과 개선안을 순서를 바꿔 보여 주어 색상 취향과 과제 수행을 분리해서 평가한다.

## 9. 디자인 제작용 브리프

자비스는 한국어 모바일 패션 비서다. 오늘 무엇을 입을지 빠르게 정하도록 돕는다. Quiet personal stylist를 컨셉으로 따뜻한 흰색과 여백을 주로 사용하고, 스톤 컬러 의류 보드, 작은 라벤더·블러시 강조, 그래파이트 주 행동 버튼을 적용한다. Tiimo에서는 먼저 정리해 주는 결과 중심 흐름, Structured에서는 오늘의 맥락과 명확한 우선순위, Indyx에서는 의류 중심 플랫레이, Whering에서는 보유 의류의 간편한 활용을 참고한다. 화면의 주 결정은 하나로 정하고 오늘 화면은 브리핑·코디 한 벌·추천 이유·착용 버튼으로 구성한다. 한국어 본문 15~16과 보조 12~13을 기준으로 읽기 쉽게 만든다. 실제 의류와 샘플 이미지, 실제 연결과 데모 상태를 명확히 구분한다. 색 비율은 초기 가설이며 사용성 관찰과 대비 확인을 통해 수정한다.
