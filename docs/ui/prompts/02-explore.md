# Phase 2 — 시안 3안 비교

> 전제: `docs/ui/01-brief.md` 확정. `app/` 본 코드는 아직 건드리지 않는다.

## 지시

brief의 방향 안에서 **서로 다른 해석 3안**을 만들어 비교하고,
사용자가 하나를 고르게 한다.

- 대상 화면은 **오늘(today)** 과 **옷장(closet)** 두 개만. 이 둘이 앱의 성격을 결정한다.
- 3안은 색만 다른 게 아니라 **구조적으로 다른 해석**이어야 한다.
  예: 선이 지배하는 안 / 면이 지배하는 안 / 여백이 지배하는 안
- 시안은 버리는 코드다. `app/` 본 파일을 수정하지 말고 별도 경로에 만든다.

## 각 안마다 명시할 것

| 항목 | 내용 |
|---|---|
| 한 줄 정의 | 이 안이 무엇으로 승부하는가 |
| 적용한 원칙 | CLAUDE.md 3절의 7원칙 중 어느 것을 강하게 밀었는가 |
| 옷 색 처리 | 색면이 UI 위에서 어떻게 읽히는가 |
| 포기한 것 | 이 안이 희생한 가치 |
| 위험 | 구현·접근성·플랫폼 위험 |

## 출력

- 3안의 실제 렌더 결과를 스크린샷으로 `docs/ui/shots/phase2/` 에 저장
- `docs/ui/02-directions.md` 에 비교표 + 권고안 1개와 그 근거
- 사용자가 고르기 전에는 Phase 3으로 넘어가지 않는다
