# Phase 5 — 출시 수준 검증

> 전제: Phase 4 전 티켓 완료.

## 지시

`docs/ui/05-verification.md` 에 **실제 확인한 결과만** 기록한다.
추정으로 채운 항목은 `미확인`으로 적는다. 통과시키지 않는다.

## 체크리스트 — 웹 가이드라인을 RN으로 번역한 것

### A. 접근성
- [ ] 모든 text/배경 조합 대비비 계산값 (본문 ≥4.5:1, 18pt+ ≥3:1)
- [ ] 모든 터치 요소 ≥44×44pt — 실측 수치로
- [ ] 모든 상호작용 요소에 `accessibilityRole` + `accessibilityLabel`
- [ ] 색만으로 정보를 전달하는 곳이 없음 (색각 이상 대응)
- [ ] 시스템 글꼴 확대(Dynamic Type) 200%에서 레이아웃이 깨지지 않음
- [ ] 스크린리더로 각 화면의 읽기 순서가 논리적임

### B. 반응형·플랫폼
- [ ] 320pt 폭(소형 기기)에서 잘림·겹침 없음
- [ ] 태블릿/와이드 웹 폭에서 레이아웃이 무너지지 않음
- [ ] iOS·Android·Web 세 곳 스크린샷 확보
- [ ] 노치/홈인디케이터 안전영역 처리
- [ ] 플랫폼 미지원 속성 사용 0건

### C. 일관성
- [ ] 하드코딩 색상 리터럴 0건 (grep으로 확인한 수치 기재)
- [ ] 토큰 외 fontSize/spacing/radius 사용 0건
- [ ] 같은 역할 컴포넌트의 중복 구현 0건

### D. 상태 완결성
- [ ] 로딩 / 비어 있음 / 에러 / 오프라인 상태가 모든 화면에 정의됨
- [ ] 긴 텍스트, 아이템 0개, 아이템 100개에서 깨지지 않음
- [ ] 다크모드 전 화면 확인

### E. 품질 게이트
- [ ] `npm run lint` 통과
- [ ] TypeScript 에러 0
- [ ] 전/후 스크린샷 대조표

## 출력

각 항목에 `통과 / 실패 / 미확인` + 근거(수치, 스크린샷 경로)를 적는다.
실패 항목은 `docs/ui/04-tickets.md` 에 후속 티켓으로 추가한다.
