# Phase 1 — 방향 확정

> 전제: `docs/ui/00-audit.md` 완료. 코드는 고치지 않는다.

## 지시

확정된 전제(사진 없음 / 출시 수준 / 기하학적 미니멀리즘)를 감사 결과와 결합해
`docs/ui/01-brief.md` 를 작성한다. 이 문서는 이후 모든 판단의 기준이 된다.

## 반드시 결론 낼 항목

1. **색 전략**
   - 옷 색(`colorHex`)이 주인공이 되려면 UI 크롬은 어느 범위의 무채색이어야 하는가
   - 현재 데이터의 옷 색 전부를 나열하고, 그 색들이 제안 배경 위에서 어떻게 보이는지 검토
   - 기능색(성공/경고/위험/선택)은 몇 개가 필요하며 각각 어디에만 쓰이는가
   - 라이트/다크 양쪽 정의

2. **타이포 전략**
   - 폰트 패밀리 결정 (시스템 폰트 유지 vs 커스텀 도입, 한글 가독성 포함해서 판단)
   - 모듈러 타입 스케일 단계 수와 비율. 27종을 **몇 종으로 줄일 것인가**
   - weight는 몇 종만 쓸 것인가 (현재 600/700/800/900 → 목표)

3. **그리드·간격**
   - 기준 단위(4pt or 8pt)와 스케일 단계
   - 화면 좌우 여백, 카드 내부 여백, 섹션 간 여백의 고정값
   - 옷장 그리드 열 수와 반응형 기준점

4. **형태 언어**
   - borderRadius 목표값 (De Stijl 원칙상 0에 가깝게 — 몇으로 할 것인가)
   - 경계선 두께 체계와 각 두께의 의미
   - 그림자를 쓸 것인가 말 것인가 (납작한 면 원칙과의 관계)

5. **아이콘·모션**
   - 텍스트 글리프를 무엇으로 대체할 것인가 (후보 2개 이상 비교: 번들 크기, 플랫폼 일관성, 기하학적 스타일 적합성)
   - 모션을 어디에만 쓸 것인가. 쓰지 않을 곳을 먼저 정한다

6. **라이브러리 결정**
   - 스타일링 레이어를 무엇으로 할 것인가
   - 각 후보의 **Expo Go 사용 가능 여부**를 반드시 명시한다 (현재 사용자는 Expo Go로 시연한다)
   - 도입 비용과 이득을 표로 비교하고 하나를 권고한다

## 규칙

- 이미 코드에서 확인 가능한 것은 묻지 말고 읽어서 채운다
- 사용자 결정이 필요한 항목은 **선택지 2~3개 + 권고안 + 근거**로 제시한다. 열어두고 넘어가지 않는다
- 합의되지 않은 내용은 `미결정`으로 표시하고 임의로 확정하지 않는다
