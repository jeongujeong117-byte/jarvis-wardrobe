## 2. 새로 확인한 모델 비교 결과

이전에 제공된 과제 제출용 ZIP에는 사진 모델의 실물이 부족했다. 이번에 별도 `03` 묶음에서 **이미 수행된 사진 선호 모델 비교**를 찾았다. 출발점을 ‘모두 새로 실험’에서 ‘기존 입력 복구와 결과 재현’으로 바꾼다.

중첩 `results_to_return.zip`에 1,964응답·1,392이미지·993응답자의 학습에 포함되지 않은 폴드에 대한 예측(OOF)이 있다. 두 분할 방식 × 7개 모델의 AUC 14개를 예측 CSV에서 다시 계산했고 저장값과 모두 일치했다. 모델을 다시 학습한 것은 아니다.

| 모델 | 이미지 분리 AUC | 응답자 분리 AUC |
|---|---:|---:|
| M0 통제 변수 | 0.595 | 0.599 |
| M1_direct 직접 측정 속성 | 0.610 | 0.618 |
| M1 측정 속성 + FashionCLIP 개념 특징 | 0.645 | 0.658 |
| M2_full 전체 이미지 특징 | **0.680** | **0.688** |
| M2_cloth_crop 옷 영역 특징 | 0.650 | 0.655 |
| M3_full 측정 속성 + 전체 이미지 특징 | 0.662 | 0.680 |
| M3_cloth_crop 측정 속성 + 옷 영역 특징 | 0.638 | 0.653 |

기록된 모델은 동결된 FashionCLIP 특징과 L2 로지스틱 회귀를 조합한다. 목표는 Q1 1~4점 중 `Q1 >= 3`이다. **AUC 0.680은 정확도 68%가 아니다.** 좋아함 응답을 싫어함 응답보다 높은 점수로 정렬하는 구분 능력의 지표다.

M2_full이 가장 높은 점추정치를 보인다. 다만 M1 대비 차이의 저장 95% 구간은 이미지 분리 [-0.0019, 0.0685], 응답자 분리 [-0.0071, 0.0585]로 0을 포함한다. 이 구간은 고정 OOF 예측에 대한 300회 근사 재표집이며 재학습 불확실성까지 포함하지 않는다. 따라서 전체 이미지 특징을 **우선 복구할 후보**로 선택하되 우위가 확정됐다고 표현하지 않는다.

이미지 분리에는 응답자가, 응답자 분리에는 이미지가 겹칠 수 있다. 둘 다 처음 보는 사람과 처음 보는 사진을 동시에 평가한 결과는 아니다. 개발 비교이며 최종 잠금 시험은 미평가, 사진 측정의 사람 검수도 미완료다. 전체 이미지 모델에는 배경·인물·시대 정보의 영향이 남을 수 있다.

추가 데이터는 각자 다른 일을 한다. ‘사진 인식’, ‘코디 조화’, ‘개인 선호’, ‘실제 착용 만족’의 정답을 하나로 합치지 않는다.

|---|---|---|---|
| 최우선 | 기존 AI Hub 이미지·응답·입력 묶음 | 이미 실험한 선호 모델을 복구 | 새 대규모 수집보다 먼저 확보 |

본인 평가 30~50회는 작동과 초기 취향 조정을 위한 제안이다. 일반 사용자 성능을 입증할 표본으로 보지 않는다. 추천을 보지 않은 아이템·미응답은 싫어함으로 처리하지 않는다. 노출 ID, 코디 구성, 상황, 선택/거절, 수정, 착용 여부, 만족, 시간, 모델 버전을 남긴다.

[AI Hub 연도별 패션 선호도 파악 및 추천](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71446)은 이미지와 응답자별 선호를 연결하는 자료다. 공개 스키마에서 `imgName`, `user.R_id`, 선호 문항을 확인했다. 스타일의 시대를 실제 응답 시각으로 사용하지 않으며, 지각 핏·인상 응답을 새 추천 시점에 이미 아는 입력처럼 사용하지 않는다. 공개 전체 규모는 로컬 보유량과 다르다.

[Polyvore 저자 카드](https://huggingface.co/datasets/mvasil/polyvore-outfits/blob/main/README.md)는 아이템 조합 관계를 제공하고 아이템 분리 설정을 설명한다. 다만 연구 전용 접근 안내와 CC BY 4.0 안내가 함께 있어 사용 조건을 확인하기 전 필수 의존성으로 삼지 않는다. [K-Fashion](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=51)은 속성·영역·스타일 인식 자료이며 개인 선호 정답과 구분한다. [Fashionpedia 이용 조건](https://fashionpedia.github.io/home/data_license.html)도 주석과 이미지의 조건이 다름을 설명한다.

AI Hub 다운로드는 신청·승인이 필요하다. 학습 결과물의 활용과 원본 자료 재배포는 조건이 다르므로 학습 사진을 공개 앱의 예시 갤러리에 그대로 넣지 않는다. 앱 시연에는 본인 소유·사용 허가된 사진을 쓴다. [AI Hub 공식 FAQ](https://www.aihub.or.kr/aihubnews/faq/list.do)

## 5. 이번 주 알고리즘 구조

**사진 선호 예측:** 기존 Q1 이진 기준과 분할을 유지해 M0 → M1_direct → M2_full을 먼저 재현한다. 특징은 한 번 계산해 저장하고 작은 회귀모형만 학습한다. 결과가 재현되면 모델·스케일러·특징 순서·인코더 버전·전처리·라벨 규칙을 함께 저장한다. 1~4점 순서형 모델과 복잡한 결합은 시간이 남을 때 비교한다.

**보유 옷 추천:** 종류·계절·활동·사용 가능 상태·기피 조건으로 후보를 만들고, 명시적 스타일 선호와 반복 제한으로 순위를 매긴다. 좋아하는 색·여유감·스타일과 코디 선택 기록으로 개인화를 시작한다. 소수의 응답으로 사용자별 큰 모델을 만들지 않는다.

두 기능의 입력은 다르다. 전신 착샷으로 학습한 점수를 개별 옷 사진의 평균 특징이나 콜라주에 바로 적용해 ‘조합의 선호 확률’이라고 표시하지 않는다. 처음에는 사진 모델을 참고 코디 탐색에 한정하고, 보유 옷 조합에는 별도 규칙·직접 입력 선호를 사용한다. 실제 조합과 사용자의 선택이 쌓이면 그 데이터로 순위 모델을 추가한다.

**추가 학습의 핵심은 앱에서 실제로 제안한 조합에 대한 반응이다.** 기존 텍스트로 속성과 거절 이유를 정리하고, 이미지 모델로 시각 정보를 표현하고, 사용자가 실제 선택한 결과로 개인화를 보완한다.

## 6. 기존 앱과 연결할 지점

[기존 앱 README](<C:/Users/woojeong/jarvis-wardrobe/README.md>)와 소스를 정적으로 확인했다. 현재 코디는 상·하의를 순환시키고 신발을 붙이는 시연 로직이며, 상황 선택이 추천 적합도 계산으로 이어지지 않는다. Gmail·날씨 등도 샘플 기능이다. 실행·실제 서버 연결은 이번에 검증하지 않았다.

1. 기존 오늘 코디 화면의 순환 조합을 `generateCandidates → filterConstraints → rankOutfits`로 교체한다.
2. 의류 자료형에 사진, 계절, 사용 가능 상태, 선호 핏·스타일을 연결한다.
3. 로컬 저장을 기본으로 옷장·취향·코디 선택·피드백을 재시작 후에도 보존한다. 기존 서버 연결은 상태 확인 후 선택적으로 사용한다.
4. 추천 ID로 노출·선택·거절·수정·착용 평가를 연결한다.

현재 자료 구조는 [wardrobe.ts](<C:/Users/woojeong/jarvis-wardrobe/src/data/wardrobe.ts>), 추천 화면은 [jarvis-screens.tsx](<C:/Users/woojeong/jarvis-wardrobe/src/components/jarvis-screens.tsx>), 의류 저장 계층은 [clothing-items.ts](<C:/Users/woojeong/jarvis-wardrobe/src/services/clothing-items.ts>)에 있다. 이 앱은 이번 자료 탐색에서 수정하지 않았다.

| 1 | 기존 학습 입력 복구, 이미지–응답 연결·라벨·버전 확인 | 누락·중복·잘못된 라벨을 집계한 입력표와 학습 가능 여부 |
| 2 | 동일 분할에서 기존 회귀 비교 재현 | 저장 결과와 차이의 원인 설명, 기준선 확보 |
| 3 | 선호 모델 저장·새 사진 추론 연결, 옷장 후보·제약 로직 작성 | 입력→점수 재현, 조건을 어기는 코디 제외 |
| 4 | 기존 화면에 추천 3개·교체·모두 거절·취향 입력 연결 | 본인 옷으로 추천 흐름 작동 |
| 5 | 옷장·선호·피드백 영속 저장, 초기 선택 기록 축적 | 앱 재시작 후 데이터 보존, 노출과 평가 연결 |
| 6 | 본인 옷으로 인식·제약·반복·설명·실패 사례 점검 | 없는 옷 추천, 세탁 중 추천, 저장 누락 등 수정 |
| 7 | 전체 흐름 점검과 사용할 수 있는 실행본 정리 | 등록→추천→교체→선택→착용 피드백 동작 |

1일차 말까지 입력 묶음이나 대응 이미지·응답이 확보되지 않으면 사진 모델 재학습은 보류하고, 직접 입력 속성·기피 조건·선호 선택에 기반한 추천을 앱에 연결한다. 이는 규칙과 초기 취향을 반영하는 시제품이며 학습된 개인화 성능으로 포장하지 않는다. 원자료 확보를 기다리며 화면·저장·추천 흐름 작업을 멈추지 않는다.

모든 일정은 지금 찾은 기존 앱을 재사용하는 전제다. 무료 로컬 실행을 기본으로 잡고 유료 API·상시 GPU 서버가 없어도 핵심 기능이 작동하도록 한다. 무료 클라우드 자원 확보나 앱스토어 심사 일정은 완료 조건에 넣지 않는다.
