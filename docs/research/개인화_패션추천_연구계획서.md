# 실제 착용 만족을 높이는 개인화 패션 추천 연구계획서

작성일: 2026년 11월 3일 | 관점: 제품 기획 + 데이터 분석 | 버전: 1.0

**수행 순서: ① 보유한 옷으로 코디 추천 → ③ 체형·취향에 맞는 스타일 탐색 → ② 새로 살 옷 추천.**

이 문서는 앞으로 수행할 연구·개발 계획이다. 제시한 표본 수, 기간, 예산, 통과 기준은 연구 설계를 위한 제안이며, 이미 얻은 결과나 성능 보장값이 아니다. 기존 자료의 수치는 첨부 보고서·실행기록에 적힌 값으로, 이번에 원자료를 재계산한 값이 아니다.

## 1. 연구의 방향과 최종 산출물

**먼저 만들어야 할 것은 ‘패션을 객관적으로 채점하는 AI’보다, 사용자의 옷장·취향·그날의 상황을 받아 실제 입을 만한 코디를 제안하고 착용 결과로 개선하는 프로그램이다.** 연구의 핵심 질문은 “개인화가 간단하지만 쓸 만한 코디 규칙보다 실제 착용 만족을 높이는가?”이다.

| 단계 | 풀어야 할 질문 | 만들 프로그램 | 다음 단계로 갈 근거 |
|---|---|---|---|
| 1. 보유 옷 코디 | 오늘 내 옷으로 무엇을 입을까? | 옷장 등록, 상황 입력, 코디 3개, 교체·거절, 착용 후 평가 | 규칙형 추천 대비 실제 효용과 사용성 확인 |
| 2. 체형·취향 탐색 | 내가 편하고 좋아하는 실루엣은 무엇일까? | 여유감·기장·실루엣 선호를 배우는 스타일 프로필 | 취향만 사용한 추천보다 추가 정보가 유용함 |
| 3. 쇼핑 추천 | 무엇을 한 벌 더 사면 옷장이 좋아질까? | 기존 옷과의 조합, 예산, 사이즈·재고를 반영한 후보 | 구매 후 활용·만족 개선, 중복·반품 문제 점검 |

초기 일정은 **1인 기획·분석·개발, 주 15~20시간, 1단계 12주**를 가정한다. 2·3단계는 각각 4~6주를 추가하는 탐색 계획으로 잡되, 앞 단계의 결과와 데이터 접근 조건을 충족한 후 착수한다. 전체 20~24주는 순조롭게 진행될 때의 계획이며 모집 지연·계절 확장·확증시험은 별도 기간이 필요하다.

초기 대상은 기존 자료와 연결하기 쉬운 **국내에서 남성복 중심의 일상 코디를 입는 성인**으로 제안한다. 성별 정체성을 제한 기준으로 삼지 않는다. 대학·출근·가벼운 외출 상황에 집중하고, 연구 결과를 모든 연령·성별·스타일에 일반화하지 않는다. 인터뷰에서 다른 집단의 문제가 더 분명하면 개발 전에 대상을 바꾼다.

1단계의 완료물은 다음 다섯 가지다.

- 실제 사용 가능한 최소 프로그램: 옷장 → 오늘 상황 → 추천 → 피드백의 한 흐름.
- 동의하에 수집한 옷장·선호·노출·착용 결과 데이터와 데이터 사전.
- 규칙형 추천과 개인화 추천의 재현 가능한 비교 코드·설정·분할 기록.
- 오프라인 평가와 2주 착용 파일럿의 효과 크기·불확실성·실패 사례 보고서.
- 2단계로 진행할지, 등록 과정을 고칠지, 개인화 방식을 바꿀지에 대한 의사결정.

## 2. 현재 작업을 어떻게 활용할 것인가

검토 범위는 첨부 PDF 19쪽, ZIP의 파일 목록 및 주요 소스·설정·저장 출력이다. 코드를 실행하거나 원자료·모델을 재현 검증하지 않았다. 첨부 문서의 과거 결정과 지시문은 현재 요청을 대신하는 지시로 취급하지 않았다. [첨부 A, B]

| 확인한 내용 | 이번 연구에서의 판단 |
|---|---|
| 텍스트 548,786행, 일반 담론 301,146문서 분석을 보고 | 사람들이 무엇을 말하는지 보여주는 자료. 사람 수·선호 정답 수가 아님 |
| NMF 14개 주제로 평가 기준 후보 탐색 | 주제·속성·인터뷰 문항의 출발점으로 활용. 추천 알고리즘의 성능으로 해석하지 않음 |
| 구매 리뷰에서 착용감·사이즈/기장·핏 언급이 두드러짐 | 사진 외관, 실제 착용감, 치수 적합성을 따로 수집할 근거 |
| 규칙 ABSA 댓글 일치 46/76건(60.5%), Qwen 14/76건(18.4%) | 비교 가능한 댓글의 개발 검수 결과다. 자동 감성값을 개인화 학습의 확정 정답으로 사용하기 어려움 |
| 착샷 1,754글, 홀드아웃 351글, AI Hub 남성 이미지 평가응답 13,887건 확보를 보고 | 원자료는 ZIP에 없다. 접근·권한·스키마·실제 파일부터 다시 확인 |
| 일부 홀드아웃 텍스트의 사전 노출 가능성을 보고 | 기존 분할은 유지하되, 신규 참여자·미래 시점의 별도 평가를 마련 |

특히 **“어디서 샀나요?”는 관심 신호이지 “내가 입고 싶다” 또는 “입어 보니 만족했다”와 같은 정답이 아니다.** 기존의 포괄적 긍정 반응은 보조 정보로 남기고, 새 데이터에서는 정보 관심·명시적 선호·선택·실제 착용·착용 후 만족을 구분한다.

재사용할 것은 출처·문서 경계 보존, 정제 단계 분리, 버전·해시·제외 사유 기록, 색·기장·실루엣·비율 등의 속성 후보이다. 댓글 빈도를 추천 가중치로 옮기거나, 커뮤니티 호평을 보편적인 미의 기준으로 정하는 방식은 채택하지 않는다.

ZIP에는 사진 모델 관련 `photo_features.py`, `image_model.py`의 경로·해시 기록이 있지만 해당 소스 자체는 포함되지 않았다. AI Hub의 13,887건 역시 첨부 참고문서상 1,954명의 4,912개 이미지에 대한 **응답 수**다. 기존 데이터를 즉시 학습 가능한 완성 자산으로 계산하지 않는다.

근거 위치: 첨부 A 물리 7~9쪽(데이터·분석), 11~13쪽(평가 문맥), 15쪽 표 10(ABSA 개발 검수), 18쪽(한계·후속 검증). 첨부 B의 `00_먼저읽기.txt`, `07_실행기록/input_manifest.json`, AI Hub 선호도 참고문서.

## 3. 제품 가설과 ‘잘 맞는 추천’의 정의

사용자 문제는 아직 인터뷰로 검증하지 않은 가설이다. 초기 세그먼트는 ① 매일 비슷한 옷만 입고 선택에 시간을 쓰는 사람, ② 옷은 있지만 조합에 자신이 없는 사람으로 나눈다. 현재 대안은 익숙한 코디 반복, 검색·SNS 저장, 지인 조언이다. 제안 가치가 실제로 있는지는 그 대안과 비교한다.

**가치 제안:** “내 옷과 오늘의 제약을 바탕으로, 추가 구매 없이 바로 입을 후보를 좁혀 주고, 거절 이유와 착용 경험을 다음 추천에 반영한다.”

| ‘잘 맞음’의 차원 | 측정 질문 | 사용하면 안 되는 대체 지표 |
|---|---|---|
| 옷끼리의 조화 | 이 상·하의·신발 조합이 자연스러운가? | 이미지가 서로 비슷한 정도만으로 판정 |
| 개인 취향 | 다른 사람 평가와 무관하게 내가 입고 싶은가? | 인기·좋아요·브랜드 인지도 |
| 상황 적합성 | 오늘 활동·날씨·드레스코드에 맞는가? | 평상시 선호 점수만 사용 |
| 착용 가능성 | 지금 입을 수 있고 움직임·촉감이 편한가? | 사진만으로 사이즈·착용감 추정 |
| 실제 효용 | 선택하고 입은 뒤에도 만족했는가? | 클릭·저장만으로 성공 선언 |

기회-해결책 구조는 다음과 같이 시작한다. 아래 문제는 발견 사실이 아니라 인터뷰에서 확인할 후보이며, 우선순위는 관찰한 빈도·불편의 강도·현재 해결 노력으로 정한다.

| 문제 후보 | 비교할 해결책 3가지 | 가장 싼 검증 |
|---|---|---|
| 아침에 고르기 어렵다 | 코디 3개 / 한 아이템 고정 후 조합 / 일주일 코디 미리 저장 | 실제 외출 전 선택 시간·거절 이유 비교 |
| 내 취향을 표현하기 어렵다 | 스타일 단어 선택 / 이미지 쌍대선택 / 기존 만족 코디 등록 | 8~12번 응답 후 본인 옷 추천의 수용 여부 |
| 등록이 번거롭다 | 사진 직접 등록 / 연구자 보조 등록 / 10개부터 점진 등록 | 등록 완료율·시간·수정 부담 측정 |

초기 제품은 옷장 등록, 착용 가능 상태, 오늘 상황, 추천 3개, 한 아이템 교체, 거절 이유, 저녁 착용 피드백을 포함한다. 가상 피팅·자동 체형 진단·쇼핑몰 통합은 후속 가설의 가치가 확인된 뒤 다룬다.

## 4. 연구 질문과 문헌 검토 계획

| 질문 | 가설과 비교 | 판단에 필요한 데이터 |
|---|---|---|
| RQ1. 이 문제가 반복되는가? | 시간·실패 경험이 실제로 존재하며 현재 대안이 충분하지 않다 | 최근 실제 옷 선택 사례, 일주일 일지 |
| RQ2. 개인화가 유용한가? | 같은 옷장·제약에서 개인화가 규칙형보다 확인된 만족 착용률을 높인다 | 무작위 비교, 선택·착용·만족 연결 기록 |
| RQ3. 복잡한 표현이 필요한가? | 이미지 특징이 태그·선호만 쓰는 모델에 추가 가치를 준다 | 같은 분할·후보에서 제거 비교, 비용·지연 |
| RQ4. 핏·실루엣 정보가 필요한가? | 본인이 입력한 여유감·기장 선호가 취향 정보만 쓴 추천보다 낫다 | 2단계 추가 비교, 편안함·재착용 의향 |
| RQ5. 추가 구매가 옷장 활용을 높이는가? | 새 상품의 단독 매력보다 기존 옷과의 활용을 고려하면 구매 후 효용이 높다 | 3단계 카탈로그·구매 후 사용·반품 이유 |

문헌이 뒷받침하는 출발점은 다음과 같다.

- 개인 옷장의 아이템 집합에서 코디를 만드는 문제는 이미 연구된 바 있다. 그러나 외부 평가자가 조합을 좋아한 결과가 소유자의 실제 착용 만족을 뜻하지는 않는다. [Tangseng 등, 2018](https://arxiv.org/abs/1804.09979)
- 같은 종류의 옷 사이 유사성과 다른 종류의 옷 사이 조화는 구분해야 한다. CLIP 코사인 유사도 하나를 코디의 정답으로 사용하지 않는다. [Vasileva 등, ECCV 2018](https://www.ecva.net/papers/eccv_2018/papers_ECCV/html/Mariya_Vasileva_Learning_Type-Aware_Embeddings_ECCV_2018_paper.php)
- 개인화된 코디 연구는 조화와 사용자 선호를 함께 다룬다. 다만 대규모 쇼핑 클릭 데이터의 결과를 작은 개인 옷장 서비스에 바로 일반화할 수 없다. [Chen 등, POG, 2019](https://arxiv.org/abs/1905.01866)
- 오프라인 정확도, 사용자 비교, 실제 서비스 실험은 서로 다른 질문에 답한다. 따라서 세 단계 평가를 연결한다. [Shani·Gunawardana](https://www.microsoft.com/en-us/research/publication/evaluating-recommender-systems/)

1~2주차에는 ACM·IEEE·CVF/ECVA·arXiv에서 `personalized outfit recommendation`, `personal wardrobe recommendation`, `fashion compatibility user study`, `fashion recommendation fit preference`를 검색한다. 2018년 이후 연구를 중심으로 선행 기반 논문도 추적하고, 한국어로 ‘개인화 코디 추천’, ‘패션 추천 사용자 평가’를 보완한다.

각 문헌에 입력·출력·데이터 출처·분할 단위·비교 모델·사람 평가·효과·한계·이용 조건을 한 행으로 기록한다. 코드 또는 평가 설계가 확인되는 논문을 우선 검토하고, 마케팅 설명만 있는 자료는 방법 근거에서 제외한다. 검색일·검색식·읽지 못한 원문도 남긴다. **이번 계획서의 조사는 핵심 원전을 선별한 검토이며, 포괄적인 체계적 문헌고찰을 완료한 것은 아니다.**

## 5. 먼저 할 사용자 연구

**인터뷰 12명 내외, 1인 30~40분**으로 시작한다. 패션 관심도 낮음/높음, 옷 선택 자신감 낮음/높음, 학생/직장인 등 생활 상황이 한쪽에 몰리지 않게 모집한다. 평소 입는 사이즈·핏 선호의 다양성도 확보한다. 편의표본이라는 한계를 기록하고, 이 수를 통계적 대표성의 근거로 쓰지 않는다.

인터뷰는 기능 소개보다 과거 행동을 먼저 묻는다.

1. 최근 외출 때 어떤 순서로 옷을 골랐나요? 실제 아이템을 떠올려 설명해 주세요.
2. 처음 고른 조합을 바꿨다면 무엇 때문에 바꿨나요? 얼마나 걸렸나요?
3. 최근 마음에 들었던 코디와 입고 나서 불편했던 코디를 각각 설명해 주세요.
4. 사진으로 좋아 보이지만 직접 입기는 싫었던 옷이 있었나요? 이유는 무엇인가요?
5. 어떤 옷을 자주 안 입나요? 세탁·사이즈·날씨·조합 중 무엇이 영향을 주었나요?
6. 스타일을 찾기 위해 실제로 사용하는 앱·저장 사진·사람·돈·시간은 무엇인가요?
7. 최근 산 옷은 기존 옷과 어떻게 입었나요? 예상과 달랐던 점은 무엇인가요?
8. 옷장 사진 10개를 지금 등록한다면 어느 단계가 부담스러운지 직접 보여 주세요.

녹음 여부는 별도 동의를 받고, 기록은 `참여자 ID / 실제 상황 / 하려던 일 / 현재 대안 / 어려움 / 해결 노력 / 원하는 결과 / 관찰 근거 / 추가 질문`으로 남긴다. “이 앱을 쓰겠나요?”의 긍정 답변만으로 수요를 확정하지 않는다.

이후 **8명 내외의 개발용 파일럿**에서 1주간 연구자가 간단한 규칙과 선호 입력으로 코디를 제시한다. 화면이 완성되기 전에도 동일한 추천 카드와 피드백 폼으로 테스트할 수 있다. 연구자 개입 시간과 추천 생성 방식을 기록해 자동화 모델 성능과 구분한다.

진행 기준 초안은 ① 최소 10개 옷 등록이 대다수에게 가능, ② 핵심 불편이 반복 관찰됨, ③ 추천 거절 이유를 분류할 수 있음, ④ 일일 피드백 부담이 감당 가능함이다. 등록 시간이 길면 자동 인식 모델보다 ‘10개부터 등록’이나 보조 등록을 먼저 실험한다. 연구자 보조 등록의 효과와 자가 등록 사용성은 따로 보고한다.

## 6. 데이터 수집과 DA 분석 설계

핵심 정답은 **본인의 옷·상황에 대한 본인의 선택과 착용 경험**이다. 외부 데이터는 표현·조화 모델을 시험하는 보조 자료로 둔다. 초기에는 참여자당 15~25개 실용 아이템을 목표로 하고, 상의·하의·신발이 모두 포함되도록 한다. 30명의 옷 약 450~750개는 작은 모델과 사용성 실험의 자료이며 대형 모델을 처음부터 학습할 규모로 보지 않는다.

| 테이블 | 핵심 필드 | 역할 |
|---|---|---|
| users | 가명 ID, 동의 버전, 선호·기피, 생활 상황 | 개인화·참여 관리 |
| items | 아이템 ID, 소유자, 사진, 종류, 색, 소재감, 계절, 여유감·기장, 사용 가능 상태 | 실제 입을 후보 구성 |
| contexts | 날짜, 활동, 드레스코드, 사용자 확인 날씨·체감, 반드시 입을 아이템 | 오늘의 제약 |
| outfits | 코디 ID, 구성 아이템 ID, 생성·모델 버전 | 추천 대상의 일관된 식별 |
| exposures | 요청 ID, 사용자, 실험 조건, 후보·순위, 시간, 추천 가능 여부 | 무엇을 보여 줬는지 복원 |
| feedback | 선택·거절, 이유, 실제 착용, 핵심 아이템 수정, 만족·편안함, 응답 시점 | 학습·평가 결과 |

모든 필드에 의미·단위·허용값·결측 코드·수집 근거를 명시한다. 사진 인식 결과에는 신뢰도와 사용자 수정 여부를 저장한다. ‘모름’, ‘해당 없음’, ‘미응답’, ‘0점’을 구분한다. 같은 요청의 재시도·중복 클릭은 ID로 묶고, 추천되지 않은 아이템을 싫어한다고 간주하지 않는다.

선호 입력은 8~12개의 이미지 쌍대선택 또는 본인의 만족 코디로 시작한다. **둘 다 싫음·비슷함·판단 어려움**을 허용한다. 라벨을 다음과 같이 분리한다: 보기 좋음 / 내가 입고 싶음 / 오늘 선택 / 실제 입음 / 입은 후 만족 / 편안함. 거절 이유는 취향·활동·날씨·핏/촉감·세탁/상태·반복·기타로 받는다.

DA 점검은 모델링 전에 진행한다.

- 모집 → 등록 → 추천 노출 → 선택 → 착용 확인 → 만족 응답의 이탈률과 분모 확인.
- 사용자별 아이템 수·응답 수, 종류·스타일·사이즈 분포, 사진 품질, 중복 이미지 점검.
- 모델 조건·사용자·기간별 결측률, 보조 등록 여부에 따른 차이 점검.
- 같은 사람·원본 이미지·변형 사진이 학습과 평가에 함께 들어갔는지 점검.
- 규칙 실패·인식 실패·취향 실패·상황 실패·착용감 실패를 구분한 오류표 작성.

원본은 보존하고 파생본에만 정제한다. 신체 사진은 1단계 필수 입력에서 제외한다. 착용 사진을 선택적으로 받으면 얼굴 가리기·위치정보 제거·열람 제한을 적용한다. 연락처와 연구 ID를 분리하고 연구 동의와 모델 재학습 동의를 구분한다. 보관기간·삭제 방법·외부 서비스 전송 여부는 모집 안내에 명시하고, 학교 제출 연구라면 착수 전에 해당 연구윤리 절차를 확인한다.

## 7. 추천 알고리즘과 구현 전략

초기 추천은 **필수 제약 확인 → 후보 조합 생성 → 순위 계산 → 다양성 조정 → 설명·수정 → 결과 기록**으로 구현한다. 사용자 옷장 밖의 아이템은 1단계 추천에 들어가지 않는다.

먼저 사용 불가·세탁 중·사용자가 제외한 아이템을 제거한다. 드레스코드와 활동상 필수 조건도 먼저 반영한다. 날씨는 사용자 확인값으로 시작해도 된다. 필수 조건을 만족하는 후보가 없으면 그 이유와 바꿀 수 있는 조건을 보여 주며, 조건을 몰래 완화하지 않는다.

상의·하의·신발과 필요한 겉옷을 조합한다. 작은 옷장은 전체 유효 조합을 비교하고, 너무 많으면 정해진 규칙으로 후보를 줄여 모든 비교 모델에 동일하게 제공한다. 결과는 ‘익숙한 조합’, ‘조금 새로운 조합’ 등 반복을 줄인 3개로 제시하되, 실험에서는 같은 다양성 정책을 사용한다.

| 모델 | 구성 | 연구 목적 |
|---|---|---|
| B0. 제약 + 규칙 | 종류 구성, 색·계절·격식의 단순 규칙, 공통 반복 제한 | 반드시 이겨야 할 실용적 기준선 |
| B1. 태그 개인화 | B0에 좋아하는 색·핏·스타일, 기피 조건, 선호 코디 반영 | 복잡한 AI 없이도 개인화 가치가 있는가 |
| B2. 이미지 특징 추가 | 동결된 일반 CLIP 또는 FashionCLIP 특징 + B1 | 사진 표현의 추가 이득과 오류·비용 비교 |
| B3. 피드백 학습 | 개발용 선택·거절·착용 기록으로 가벼운 순위 모델 학습 | 충분한 라벨이 생겼을 때만 추가 |

첫 구현은 B0와 B1이다. B2는 후보 특징 추출기로 시험한다. FashionCLIP 공식 모델 카드는 영어·제품 사진 중심의 편향과 실제 사용 맥락 검증 필요를 알린다. 한국어 자유입력과 사용자가 찍은 구겨진 옷 사진에서 성능을 별도 점검하고, 인식 결과를 수정할 수 있게 한다. [FashionCLIP 모델 카드](https://huggingface.co/patrickjohncyh/fashion-clip)

점수 구조는 다음처럼 해석 가능한 항목으로 시작한다.

`score(user, outfit, context) = 조합 적합성 + 개인 선호 + 상황 적합성 - 반복 부담`

이는 구조를 설명하는 식이며 고정된 수치 가중치의 근거가 아니다. 가중치는 개발용 데이터에서만 조정하고 개인 취향의 차이를 허용한다. 필수 제약 위반은 낮은 점수로 상쇄하지 않고 후보 단계에서 제거한다. 이미지 유사성은 유사 아이템 검색과 선호 표현에 사용하고, 서로 다른 종류의 조화를 판정하는 유일한 항으로 쓰지 않는다.

초기 사용자에게는 선호 입력에서 좋아한 속성·코디의 표현을 이용한다. 행동이 누적되면 쌍대선택 학습이나 규제가 있는 작은 모델을 비교하되, 사용자별 데이터가 적으면 공통 모델·직접 입력 선호를 유지한다. 미노출과 미응답은 부정 라벨로 학습하지 않는다. 대형 생성 모델·강화학습 도입은 단순 모델의 한계와 데이터 규모가 확인된 이후의 선택이다.

설명은 “선호한 여유 있는 상의와 등록한 검정 바지를 조합했습니다”처럼 실제 사용한 속성을 근거로 생성한다. LLM을 쓰더라도 검증된 필드의 문장화 역할부터 시작한다. 보지 못한 신체 특성이나 확인되지 않은 소재·사이즈를 만들어 설명하지 않는다.

## 8. 오프라인 평가와 데이터 분할

오프라인 평가는 후보를 줄이고 오류를 발견하는 단계다. 실제 착용 만족을 대체하지 않는다. 비교할 모델, 특징, 주요 지표, 튜닝 범위와 최종 시험 시점을 먼저 기록한다.

| 평가 | 분할·비교 원칙 | 주요 지표 |
|---|---|---|
| 새 사용자 | 개발 참여자와 최종 평가 참여자를 분리. 최종 사용자의 사전 선호 입력만 허용 | 본인 코디 쌍대선택 일치, 추천 3개 수용 여부 |
| 재방문 사용자 | 전체 시간축에서 과거로 학습하고 미래를 평가 | 시간에 따른 수용·착용 만족, 반복률 |
| 새 아이템·외부 조화 | 원본 아이템/사진 단위로 분리, 중복·변형도 같은 묶음 | 조화 판별, 필요시 FITB·AUC |

개발용 파일럿과 최종 착용 파일럿의 참여자는 원칙적으로 분리한다. 최종 참여자의 초기 선호 입력은 사전에 정한 개인화 절차의 입력이며, 전역 가중치 튜닝에는 사용하지 않는다. 별도로 보류한 평가 응답과 착용 결과는 추천에 다시 넣지 않는다. 전체 사용자의 미래 행동을 학습에 포함하는 시간 누출을 피한다. [Ji 등](https://arxiv.org/abs/2010.11060)

전처리 기준·스케일링·속성 선택·학습 가중치는 개발 데이터에서 결정한다. 기존 351개 홀드아웃은 과거 노출 가능성을 명시한 별도 자료로 남기고, 새 확인 연구의 독립 시험으로 이름만 바꾸지 않는다.

개발 평가에서는 같은 사용자의 같은 후보 코디를 B0·B1·B2가 정렬하게 한다. 0~3의 ‘내가 입고 싶은 정도’를 직접 평가한 공통 후보 묶음에서는 NDCG@3를 사용할 수 있다. 평가하지 않은 코디를 자동으로 0점 처리하지 않는다. 일부 후보만 평가했다면 ‘고정 평가 후보 내 순위 성능’으로 범위를 명시한다. 모두 0점인 묶음은 NDCG가 정의되지 않으므로 그 발생률을 따로 보고하고 NDCG 평균에서 제외한다. 전체 요청 기준 수용률에는 실패로 포함해 어려운 사례가 지표에서 사라지지 않게 한다.

보조 지표는 추천 3개 중 수용 가능한 코디 비율, 하드 제약 위반율, 아이템·코디 커버리지, 유사 코디 반복, 응답 시간이다. B2와 B1, 개인 선호를 제거한 모델과 전체 모델을 비교해 복잡성의 추가 가치를 확인한다. 대조군보다 후보를 더 많이 주거나 다른 후보 집합을 쓰지 않는다.

임의로 뽑은 쉬운 음성 후보 몇 개를 이긴 정확도는 전체 후보에서 좋은 순위를 보장하지 않는다. 후보 샘플링이 필요하면 수·구성·난이도·시드를 고정하고 범위를 공개한다. [Krichene·Rendle, 2020](https://research.google/pubs/on-sampled-metrics-for-item-recommendation/)

외부 데이터 후보는 Polyvore의 아이템 분리 설정과 iFashion이다. 공개 데이터·다운로드 링크가 서비스 사용 허가를 뜻하지 않는다. Polyvore 저자 카드에는 연구 전용 접근 안내와 CC BY 4.0 안내가 함께 있어 조건 확인을 선행한다. POG 저장소도 이번 확인만으로 상업 이용 허가를 확정할 수 없다. 이용 범위가 불명확하면 참여자 동의 데이터와 직접 제작·허가된 예시로 초기 연구를 진행한다. [Polyvore 카드](https://huggingface.co/datasets/mvasil/polyvore-outfits/blob/main/README.md), [POG 저장소](https://github.com/wenyuer/POG)

## 9. 핵심 검증: 실제 사람의 2주 착용 파일럿

**모집 36명, 완료 목표 24~30명, 14일 관찰**을 운영 초안으로 제안한다. 이는 모집·사용성·효과 크기를 알아보는 탐색적 파일럿이며, 작은 개선을 확정할 검정력을 보장하는 표본 수가 아니다. 등록·연습 완료 후 무작위배정하고, 모집·배정·완료 인원을 따로 보고한다. 주분석은 모든 무작위배정자를 포함하며, 중단 후 남은 배정일도 ‘확인된 성공’은 0으로 기록한다. 동의 철회로 삭제한 데이터의 제외 수·규칙은 별도로 기록한다.

최종 비교는 **B0와 개발 단계에서 선택한 개인화 모델 하나**로 제한한다. 같은 화면, 추천 수, 알림, 후보 생성 규칙, 필수 제약을 사용한다. 추천 모델 이름을 사용자에게 표시하지 않는다. 연구 중 전역 모델·가중치·개인 선호 프로필은 고정하고, 세탁 상태·오늘 활동처럼 변하는 조건만 공통 규칙으로 갱신한다. 이 시험은 초기 선호 기반 개인화의 효과를 검증한다. 지속 학습 효과는 후속 연구에서 고정 프로필과 ‘과거 피드백만 갱신하는 사전 정의 정책’을 별도로 비교한다.

기본 설계는 참여자 안에서 날짜별 조건을 무작위 배정하는 방식이다. 시작 전에 14일의 연구 대상 날짜를 정하고, 사용자별로 A/B를 균형 있게 배정하며 요일·전후반 편중을 줄인다. 하루의 재요청은 같은 조건을 유지한다. 사용하지 않은 배정일도 기록한다. 실제 무작위화 규칙·시드·배정표는 시작 전에 고정한다.

직전 코디와 학습 기억이 다음 날에 영향을 줄 수 있다. 양 조건에 같은 반복 제한을 적용하고 직전 조건·기간을 기록한다. 따라서 이 시험은 **이 교차 사용 환경에서의 단기 효과**를 추정한다. 장기 습관·지속 개인화 효과는 다음 연구에서 사용자 단위 A/B와 더 긴 기간으로 검증한다.

| 시점 | 사용자 행동 | 기록 |
|---|---|---|
| 시작 | 옷장 점검, 선호 입력, 연구 일정 설정 | 초기 프로필, 등록 시간·도움 여부 |
| 아침 | 오늘 상황 확인, 추천 3개 확인 | 조건·후보·순위·제약·추천 실패 |
| 선택 | 하나 선택, 일부 교체 또는 모두 거절 | 선택시간, 변경 아이템, 거절 이유 |
| 저녁 | 입었는지, 만족·편안함 1~5, 수정 여부 | 실제 결과와 미응답 구분 |
| 종료 | 가장 유용·불편했던 날 설명 | 실패 원인, 계속 사용할 이유·장벽 |

1차 지표는 **확인된 만족 착용률**로 정한다. 각 배정일에 추천 3개 중 하나의 핵심 구성(상의·하의·신발)을 그대로 입고 만족도가 4~5점이라고 확인되면 1, 그렇지 않거나 확인되지 않으면 ‘확인된 성공’은 0이다. 겉옷·액세서리 추가의 허용 범위는 시작 전에 정한다.

`확인된 만족 착용률 = 만족 착용이 확인된 배정일 수 / 전체 연구 배정일 수`

이 지표는 **확인 가능한 제품 효용과 참여를 함께 측정하는 운영 지표**다. 미응답을 실제 미착용이라고 단정하는 지표가 아니다. 미응답률을 조건별로 함께 공개하고, 응답일만의 착용 만족률·미응답의 성공 가능성을 바꾼 민감도 분석을 병기한다. 일부 아이템을 교체한 활용은 별도 보조 성과로 보고한다.

선택률·등록 완료율·선택시간·만족도·편안함·제약 위반·추천 실패·반복·응답률은 보조 지표다. 선택하지 못한 날을 선택시간 분석에서 누락하지 않도록 실패율과 함께 보고한다. 실제 착용은 자기보고임을 명시하고, 사진 제출을 의무화하지 않는다.

## 10. 분석 방법과 진입·보류 기준

분석 단위의 중심은 **사람**이다. 한 사람의 14일을 14명의 독립 사용자처럼 계산하지 않는다. 주 분석은 사용자별로 개인화 조건과 기준선 조건의 확인된 만족 착용률 차이를 계산한 후 사람에 같은 가중치를 주어 평균한다. 차이는 퍼센트포인트(pp)로 보고한다.

95% 신뢰구간은 사용자 단위 재표집으로 반복 관찰을 보존해 구한다. 소규모에서 구간이 불안정할 수 있음을 밝히고, 사전 배정 구조를 보존한 무작위화 검정 또는 사용자·기간을 고려한 모형을 보조 분석으로 정한다. 모형을 결과에 맞춰 바꾸어 유의한 결과를 찾지 않는다.

주요 결과 표에는 배정자·완료자·배정일·노출일·응답일, 조건별 성공률, 사용자별 차이의 분포, 평균 차이와 구간, 미응답 민감도, 실패 이유를 넣는다. 신규 스타일·사이즈·자신감 수준별 결과는 탐색적이며 작은 하위집단의 우열을 확정하지 않는다. 여러 지표를 확증 검정하면 검정군과 다중비교 보정도 미리 정한다.

**최소 의미 개선량의 초안은 +10pp**다. 예를 들어 30%에서 40%로 늘어나는 변화이며 ‘10% 상대 증가’와 다르다. 인터뷰에서 기대 효용·추가 입력 부담을 확인한 후 최종 연구 전에 정한다. 임계값은 문헌이 보장하는 값이 아니라 제품의 의사결정 기준이다.

| 관문 | 통과 기준 초안 | 미달 시 행동 |
|---|---|---|
| 데이터·사용성 | 파일럿의 80% 이상이 최소 등록을 완료, 10개 등록 중앙시간 15분 이내 | 등록 절차·보조 입력부터 개선 |
| 추천 실행성 | 시험 시나리오의 필수 제약 위반 0건, 실패 시 명확한 안내 | 순위 모델보다 필터·데이터 수정 |
| 개인화 효용 | 차이 추정치 +10pp 이상, 95% 구간 하한이 0 초과, 주요 사용성·편안함 악화 없음 | 효과 확정 보류, 아래 두 경우로 분기 |
| 불확실한 효과 | 추정치가 유망하지만 구간이 넓거나 0을 포함 | 효과 확정 보류, 다음 연구를 새로 설계 |
| 효과 부족·부작용 | 복잡성 대비 이득이 작거나 반복되는 불편·오류 | 단순 모델 유지, 원인별 재설계 |

개인화 효용 기준을 충족하면 제한된 후속 연구로 진행한다. 위 기준 중 ‘악화 없음’은 2주 파일럿에서 큰 문제를 놓치지 않았다는 운영 판단이며 안전성·동등성을 통계적으로 입증한 의미는 아니다. 편안함 평균 하락, 특정 사용자에게 집중되는 추천 실패, 응답률의 큰 조건 차이를 반드시 검토한다.

12주 이후 독립적으로 시행할 확증시험의 표본 수는 이번 2주 착용 파일럿의 사용자별 차이 분산·반복 상관·이탈률을 사용해 계산한다. 최소 의미 효과·양측 유의수준 0.05·검정력 80% 이상을 목표로 다음 설계에 맞게 계산 또는 시뮬레이션한다. 현재 수집 전인 분산을 꾸며 숫자를 확정하지 않는다. 유의하지 않다는 이유로 같은 시험을 임의 연장하거나 중간 성과가 좋을 때 조기 종료하지 않는다.

## 11. 프로그램 구조와 기능 완료 기준

연구용 프로그램은 모바일 브라우저에서 쓸 수 있는 가벼운 웹 형태로 시작한다. 핵심은 화면 수보다 **추천 노출과 후속 결과를 같은 ID로 연결하는 것**이다. 기술 선택은 기존 개발 환경에 맞추되, 화면·추천 로직·데이터 저장·분석 코드를 분리한다.

| 구성 | 최소 역할 | 완료 확인 |
|---|---|---|
| 옷장 화면 | 사진·태그 등록/수정, 사용 가능 상태 | 잘못 인식한 종류·색을 사용자가 수정 가능 |
| 오늘 화면 | 활동·날씨·기피·고정 아이템 입력 | 필수 조건을 충족할 수 없으면 이유 표시 |
| 추천 서비스 | 후보 생성, 기준선·개인화 순위, 버전 기록 | 같은 입력·시드·버전의 결과를 재현 가능 |
| 추천 카드 | 본인 옷 3개 코디, 이유, 교체·모두 거절 | 존재하지 않는 옷·상품 설명이 나오지 않음 |
| 피드백 화면 | 선택·실제 착용·만족·거절 이유 | 수정 착용·미응답·미착용을 구분 |
| 분석 저장소 | ID 연결, 실험 배정·노출·오류 로그 | 노출 없는 클릭, 중복 요청, 누락 연결 탐지 |

구조는 `사용자 입력 → 옷장·상황 저장 → 공통 제약 필터 → 후보 생성 → 버전별 순위 → 노출 로그 → 착용 피드백 → 분석`이다. Python 추천 모듈, 관계형 데이터 저장, 이미지 파일 저장을 분리하는 정도로 시작할 수 있다. 대형 인프라보다 버전·분할·실험 설정을 재현하는 데 먼저 시간을 쓴다.

검증 시나리오는 최소한 세탁 중인 옷 제외, 상의/하의 부족, 기피 아이템 제외, 동일 요청 재시도, 전혀 마음에 들지 않음, 사진 인식 수정, 피드백 미응답, 삭제 요청, 실험 조건 유지 등을 포함한다. 추천 속도는 개발 기기의 값만 제시하지 않고 파일럿 환경의 중앙값·상위 지연도 측정한다.

연구 데이터는 가명 ID로 분석하고, 접근 가능한 원본·파생본·보고용 집계의 범위를 나눈다. 실제 배포 전에 참가자의 동의 범위를 넘어 외부 API로 사진을 보내는 경로가 없는지 확인한다. 모델 품질 문제와 수집·로그 오류를 분리해 추적한다.

## 12. 후속 단계: 스타일 탐색과 쇼핑 추천

**2단계: 체형·취향에 맞는 스타일 탐색, 추가 4~6주.** 질문은 “몸을 자동 분류하면 정답이 나오는가?”보다 “본인이 선호하는 여유감·기장·실루엣을 알면 추천이 좋아지는가?”로 정한다. 외부 시선의 매력도와 사용자의 편안함·자기표현을 구분한다.

수집 순서는 좋아하는 핏·기장 → 가진 옷의 편한/불편한 부위 → 필요할 때만 선택적 의류 실측·신체 치수이다. 강조하거나 덜 드러내고 싶은 부분은 선택적으로 받는다. 키·몸무게만으로 체형 등급이나 ‘어울림’을 확정하지 않는다.

비교군은 1단계 취향 모델, 실험군은 여유감·기장·실루엣 정보를 추가한 모델이다. 주지표 초안은 ‘배정된 비교일 중 실제 착용하고 나다움·편안함이 모두 4~5점으로 확인된 날의 비율’이며 사용자별 차이로 비교한다. 1단계와 같이 미응답·수정 착용을 별도 보고한다. 사진에서 예뻐 보이는 결과와 치수상 맞는 결과를 별도 평가한다. 가상 피팅 이미지는 실제 사이즈 적합성의 증거로 쓰지 않는다.

진입 조건은 1단계의 등록·추천 흐름이 유지되고, 오류 분석에서 핏·실루엣 정보 부족이 반복적으로 드러나는 것이다. 이 정보가 부담만 늘리면 선택 입력으로 남기거나 수집을 줄인다. 다른 스타일·연령·체형으로 확장할 때는 새로운 모집과 검증이 필요하다.

**3단계: 새로 살 옷 추천, 추가 4~6주.** 질문은 “이 상품이 예쁜가?”에서 “이 한 벌이 현재 옷장에 실제로 유용한가?”로 확장한다. 예산·구매 의도·보유 중복·사이즈·재고·반품 가능 정보와 갱신 시점을 확인할 수 있는 카탈로그가 먼저 필요하다.

상품 점수는 개인 선호와 함께 기존 옷으로 만들 수 있는 **유효하고 서로 다른** 코디의 증가, 자주 입는 상황의 해결, 중복 부담, 예산을 고려한다. 색만 조금 다른 조합을 수백 개로 세어 효용을 부풀리지 않는다. ‘구매하지 않아도 됨’도 정당한 결과로 제공한다.

초기 비교는 일반적인 취향 유사 상품 추천과 옷장 활용을 반영한 추천이다. 구매의향·저장은 탐색 지표로만 쓰고, 실제 구매자는 수령 후 2~4주 사용·만족·사이즈 문제·반품 이유를 추가 추적한다. 주지표 후보는 ‘전체 배정 사용자 중 추천 상품을 구매하고 기존 옷과 실제 활용해 만족을 확인한 비율’로 정하되, 구매 압박·중복 구매도 함께 점검한다. 구매자만의 만족도 비교는 선택편향이 있어 인과효과로 해석하지 않는다. 구매가 없으면 구매 후 효용은 미검증으로 남기며, 추적은 4~6주 개발 뒤까지 이어질 수 있다.

카탈로그 접근·이용 조건이나 최신 재고·사이즈 정보가 확보되지 않으면 제한된 허가 상품으로 연구용 비교를 진행하고, 실시간 쇼핑 서비스로 완성됐다고 표현하지 않는다. 수익화·제휴 수수료는 효용 검증 후 검토하며 추천 순위가 광고 목적에 의해 달라지는지 구분한다.

## 13. 12주 실행 일정과 자원 계획

| 주차 | 핵심 작업 | 남겨야 할 결과·의사결정 |

| 1 | 자료 접근·권한·파일 확인, 연구 질문·대상 설정, 문헌표 시작 | 데이터 목록, 가정 목록, 인터뷰 모집안 |

| 3 | 8명 내외 보조 추천 파일럿, 선호·거절 문항 시험 | 등록 부담·피드백 가능성, 진행/수정 결정 |
| 4 | 데이터 사전·옷장·로그 구현, B0 규칙 추천 | 종단 간 최소 흐름, 제약 실패 시나리오 통과 |
| 5 | B1 개인화, 사용자 수정·거절·피드백 연결 | 태그 개인화 기준선, 재현 가능한 설정 |
| 6 | B2 특징 비교, EDA·오류 분석, 최종 모집·등록 시작 | 추가 모델의 필요성, 최종 후보 1개 선택 |
| 7 | 사용성 보완, 오프라인 비교, 문항·지표 정리 | 시험 프로토콜·분석계획·코드·버전 잠금 |
| 8 | 최종 참여자 등록·연습 완료 | 배정표, 초기 프로필, 데이터 연결 점검 |
| 9~10 | 14일 실제 착용 비교 | 모델 변경 없이 운영, 장애·이탈·응답 기록 |
| 11 | 사용자 단위 분석, 미응답 민감도, 종료 인터뷰 | 효과·구간·실패 유형·가정 검토 |
| 12 | 보고서·데모·재현 패키지 정리 | 2단계 진입/추가 연구/범위 축소 결정 |

모집은 1주차부터 준비하고, 최종 시험 참가자의 결과를 개발에 사용하지 않는다. 36명 모두 등록하면 540~900개 아이템을 다뤄야 하므로 자가 등록을 6~8주에 분산한다. 6주차까지 B0/B1과 로그 연결이 완성되지 않으면 B2·B3를 생략한다. 8주차에 배정·사용성이 불안정하면 착용 비교를 연기한다. 기간이 부족하면 인터뷰 + B0/B1 + 소규모 사용성 연구로 산출물을 줄이고 효과 확정 주장을 하지 않는다.

예산은 시장 견적이 아닌 **1단계 운영 배정 예시**다.

| 항목 | 계산 예시 | 금액 |
|---|---|---|
| 인터뷰 사례비 | 12명 × 2만원 | 24만원 |
| 개발 파일럿 사례비 | 8명 × 3만원 | 24만원 |
| 최종 착용 파일럿 사례비 | 최대 36명 × 5만원 | 180만원 |
| 호스팅·저장·제한적 추론/학습 | 사용량 상한을 정한 배정 | 10~30만원 |
| 예비비 | 재모집·운영 보완 | 30만원 |
| 합계 | 인건비·별도 기기·상품 구매 제외 | **268~288만원** |

지급액은 긍정 평가나 구매에 연동하지 않는다. 이탈자에게도 완료한 절차에 비례해 지급하는 기준을 안내한다. 예산이 부족하면 표본을 줄인 연구를 사용성·탐색 연구로 명시하고, 수백 개의 반복 응답을 큰 독립 표본처럼 포장하지 않는다. 2·3단계 참여 보상·카탈로그·구매 후 추적 예산은 결과를 보고 별도로 잡는다.

1인 수행 시 기획·인터뷰·개발·분석을 주차별로 묶는다. 통계 설계는 시험 시작 전 한 차례 검토받고, 속성·실패 이유 코딩은 일부를 다른 검토자와 비교하면 품질을 높일 수 있다. 도움을 확보하지 못하면 단독 검토의 한계를 보고서에 적는다.

## 14. 제공한 스킬의 선정과 실제 적용

사용자가 제시한 `skills_popular.csv`와 `Skill List.md`를 기준으로 과업 적합성을 검토했다. 목록의 인기도는 효과 검증 결과로 보지 않았다. 원본 ZIP 보관함을 찾지 못한 스킬은 목록의 공식 GitHub `SKILL.md` 원문을 읽었다. 설치나 부속 코드를 실행한 것이 아니라, 다음 여섯 스킬의 절차를 이번 계획서에 적용했다.

| 목록 ID·스킬 | 선정 이유 | 이번 문서에 적용한 결과 |
|---|---|---|
| S011 interview-script | 미래 사용 의향보다 실제 행동을 확인 | 5절 과거 사례 중심 질문·기록 양식 |
| S015 opportunity-solution-tree | 사용자 문제와 기능을 구분 | 3절 문제별 세 대안과 값싼 검증 |
| S010 create-prd | 대상·가치·기능·출시 범위를 연결 | 1·3·11절의 제품 범위·가치 제안·완료 기준 |
| S227 exploratory-data-analysis | 관측 단위·결측·편향·누출 점검 | 6·8절 데이터 사전·이탈 경로·분할 점검 |

| S234 statistical-analysis | 반복측정·효과 크기·불확실성 반영 | 9·10절 사람 단위 분석·신뢰구간·표본 계획 |

스킬은 사용자 목적에 맞게 적용했다. 알려지지 않은 대상 세부사항·기간·예산은 가정으로 표시했고, 질문에 대한 사용자의 답인 ‘1 → 3 → 2’ 순서를 반영했다. 아직 데이터를 수집하지 않았으므로 EDA 결과·검정 결과·검정력을 계산했다고 주장하지 않는다.

S236 `ab-test-analysis`도 검토했지만, 이번에는 통계 설계의 주 스킬로 채택하지 않았다. 결과 해석 중심이고 제시된 간단한 표본수 식만으로는 검정력과 반복측정 의존성을 충분히 다룰 수 없기 때문이다. 유의하지 않은 결과를 보고 같은 시험을 임의 연장하는 방식도 적용하지 않았다. 코드 생성·배포·영상·홍보 스킬은 연구계획 작성에 우선 필요하지 않아 제외했다.

다음 주 바로 시작할 작업은 다섯 가지다.

1. 1단계 대상·사용 상황·성공 지표의 초안을 한 장으로 고정한다.
2. 기존 원자료의 실제 위치·이용 조건·스키마와 누락된 코드를 확인한다.
3. 인터뷰 12명 모집 기준과 30분 질문지를 준비한다.
4. 옷 10개 등록, 코디 3개, 거절·착용 피드백만 있는 시험 흐름을 만든다.
5. 연구 가정·변경 이유·문헌·데이터 버전을 한 기록에 남기기 시작한다.
